02 — Key-Value Store
Redis as Managed Cache
Explore Redis as an in-memory key-value store. Set, get, list, and delete arbitrary keys directly through the API. This module introduces managed caching and the operator workflow: provision a Redis instance, wire it to the API container via REDIS_URL, then verify connectivity.
required env vars
REDIS_URL = redis://<host>:6379 # required
Quick start — run Redis locally:
docker run -d -p 6379:6379 redis:7

Then restart the API with the env var set:
REDIS_URL=redis://localhost:6379 docker compose up api
// debug tips
503 on GET /keys, GET /{key}, POST /keys, DELETE /{key} REDIS_URL is not set on the API container. Note: GET /status always returns 200 (even unconfigured) — use it to confirm the variable is missing.
connected: false in GET /status Redis is configured but unreachable at the given URL. Check that the Redis container is running and the hostname/port in REDIS_URL is correct.
404 on GET /api/redis/{key} The key does not exist in Redis. Use POST /api/redis/keys to create it first, or GET /api/redis/keys to list what exists.
Keys disappear after a Redis restart Redis stores data in memory by default. Enable persistence (AOF or RDB snapshots) on your Redis instance if you need data to survive restarts.
