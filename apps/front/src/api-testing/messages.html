01 — Messages
Persistent Message Board
Post messages with a text body and author name, then retrieve the full list. The storage backend is swappable at runtime — in-memory by default, upgrading to Redis or a cloud database via environment variables. Use GET /api/config to inspect which backend is currently active.
expected result
GET /api/messages returns a JSON array (empty [] on a fresh deployment). POST /api/messages replies 201 with the created record — load the list again to see it appended.

// debug tips
Empty list [] from GET /api/messages Expected on a fresh start — no messages have been created yet. Use POST to add the first one.
Messages lost after a redeploy In-memory storage is ephemeral. To persist data, configure a backend on the API: REDIS_URL or a cloud storage connection string.
400 on POST /api/messages The text field is required and cannot be blank. author defaults to "Anonymous" if omitted.
500 on any endpoint Server-side error. Inspect the API container logs in your cloud platform.
