02 — Key-Value Store
Redis as Managed Cache
Explore Redis as an in-memory key-value store. Set, get, list, and delete arbitrary keys directly through the API. This module introduces managed caching and the operator workflow: provision a Redis instance, wire it to the API container via REDIS_URL, then verify connectivity.
expected result
With Redis wired up, GET /status reports connected: true and the key operations return 200/204. Without REDIS_URL, /status still answers 200 but key operations return 503 — that's the signal the backend isn't configured yet.
Debug & configure
required env var · set on the API
REDIS_URL=redis://<host>:6379
Provision a managed Redis (or a Redis container) in your cloud environment, then set REDIS_URL on the API service and redeploy. This page calls the API through:

// debug tips
503 on GET /keys, GET /{key}, POST /keys, DELETE /{key} REDIS_URL is not set on the API. Note: GET /status always returns 200 (even unconfigured) — use it to confirm the variable is missing.
connected: false in GET /status Redis is configured but unreachable at the given URL. Check the instance is running and the host/port in REDIS_URL is correct.
404 on GET /api/redis/{key} The key does not exist. Use POST /api/redis/keys to create it first, or GET /api/redis/keys to list what exists.
Keys disappear after a Redis restart Redis stores data in memory by default. Enable persistence (AOF or RDB snapshots) if you need data to survive restarts.
